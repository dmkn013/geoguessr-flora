# 2026-08-30 (2) ストリートビュー連携と写真の注釈

## やったこと

1. **点のクリックでその座標のGoogleマップを開く**（別タブ）
2. **実写に「どこを見るか」の枠を重ねた**（48種・93枠）。「枠」ボタンで表示切替
3. **イトスギの画像を差し替えた**。崖に生える野生種（広がった樹形）で、
   tells の「細く直立した濃緑の円柱」が写っていなかったため

## 途中で判明した前提のずれ（重要）

ユーザーから「その地点の写真のどこに植物が映っているか」を出したい、
という要望が出たが、**点ごとの検証済み写真は存在しない**。

点は `ranges.py` の矩形から `sample_points.py` が乱数で散らしたもので、
陸地判定しか通していない。**個々の点に「その木がある」確認は無い**。

これはユーザーの理解とずれていた（「その地点に本当にその植物があるわけではないのか」）。
原因はこちらの説明不足で、READMEが点を
「ホバーで種名・示す地域・座標が出る」と書いていたため、
1点1点が特定の場所を指しているように読めていた。

対応として:
- READMEに「点が意味するもの」の節を追加し、
  **面（分布域）は本物・個々の点は表示上のもの**と明記
- 画面のヘッダにも同じ趣旨を1行入れた
- 点クリックは「確認済みの場所を見せる」ではなく
  **「この辺りを自分で見に行く」導線**として位置づけた

## 詰まったこと: `map_action=pano` は使えない

最初 `https://www.google.com/maps/@?api=1&map_action=pano&viewpoint=lat,lon` を使ったが、
**その座標にパノラマが無いと黒画面**になる。
点は道路上ではなく分布域内のランダムな位置なので、試した座標は全滅した。

→ `https://www.google.com/maps/@lat,lon,13z/data=!5m1!1e4`（地図＋SVレイヤ）に変更。
地図が開いてペグマンを近くの道に落とす形になり、
「近くの道を探す」というGeoGuessrの実際の操作にも近い。

## 注釈の方針

- 座標は0〜1の相対値（`annotations.py`）。縮小しても崩れない
- **自動検出は使わない**。誤検出した枠は
  「ここを見ろ」と間違った場所を自信ありげに指すので、枠が無いより悪い
- `check_annotations.py` で1枚ずつ描画して目視。ずれていたら直す
  （実際に grasstree / baobab / oilpalm / araucaria_ang / datepalm / poplar を修正した）
- **写真に写っていない特徴には枠を作らない**。
  ポプラの写真は「並木」ではなく散在した林だったので、
  tells の「一列に密植」ではなく、実際に写っている樹形と立地に枠を付けた
