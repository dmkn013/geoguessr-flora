# 2026-08-29 GeoGuessr 植生メタアトラスを作った（新規プロジェクト）

リポジトリ: OneDrive 配下（同期・git init 済み）
公開先: https://claude.ai/code/artifact/6075d72d-176c-4719-ba97-5f40199e7361

## やったこと

「世界地図に点を打ち、点に写る植物を色分けし、ホバーで画像と植物名が出る」という
GeoGuessr学習用の教材を作った。**48種 / 2,785点**。自己完結した1枚のHTML。

### 経緯と設計判断

1. **画像ソース**: 当初 Street View を想定したが、Google Maps Platform の規約が
   取得画像の保存・再配布を制限しており、**Artifactとして公開すると再配布に当たる**。
   → Mapillary（CC-BY-SA・無料API）を選択。ただしトークン発行が未了。
2. **点の作り方**: 「Street Viewをランダムに引いて写った植物を同定する」順序は歩留まりが悪く、
   かつ「植物→地域」という肝心の知識が出てこない。
   → **既知の分布から点を置く**逆順に変更。見た目（同色クラスタ）は要望どおりのまま。
3. **色数**: 最初38色に分けたが、ユーザー指摘で **tab10 の10色**へ。
   色の役割を「種の識別」から**「隣接する種の区別」**に変え、
   地理的な隣接グラフを作って貪欲彩色（`palette.py`）。48種でも衝突1件、
   同色ペアの最小距離19.3度を確保。種の識別はホバーのラベルが担う。
4. **点の増量とカバー率**: 215点→2,785点。手打ちアンカーをやめ、
   **分布域を矩形で定義してサンプリング**（`ranges.py` / `sample_points.py`）。
   海に落ちた点は**地図に使っているのと同じ陸地ポリゴン**で弾く
   （別ソースだと「地図では海なのに点がある」ズレが出る）。
5. **空白地帯**: カナダ・中央アジア・インド・中国内陸・豪州内陸・メキシコが空だったので
   その地域で実際に効く10種を追加（38→48種）。
   一方**サハラ内陸・北極圏・北米大平原は意図的に空けた**。
   手がかりになる植生が無い場所を埋めると教材として嘘になる。

### 技術メモ

- 地図は world-atlas の TopoJSON(land-110m, 55KB) をデコードして SVG パス化。
  投影は**正距円筒**。緯度経度→ピクセルが1行で済み、点の配置とホバー判定が単純になる。
- **日付変更線をまたぐリングはパスを切る**。切らないと地図を横断する帯が出る
  （フィジー約17°S・チュクチ半島約70°N で実際に発生）。
- 2,785点あるのでズーム時に個別 `setAttribute` は重い。
  **CSS の `r` プロパティを変数1つで動かす**方式に変更。

## 詰まったこと

- **プレビュー側のバグを生成側のバグと誤診した**。日付変更線対策でサブパスに切ったのに
  帯が消えず、データを疑ったが、原因は**プレビュースクリプトが `M` を無視して
  全点を1ポリゴンとして描いていた**こと。測定系を先に疑うべきだった。
- **Wikimedia のレート制限**。4回連続で叩いて `Too many requests` を食らい、
  HTMLのエラーページが `.jpg` として保存されて PIL が落ちた。
  → **1.5秒間隔＋連絡先入り User-Agent** が必要（ポリシー要件）。

## 次回やること（川崎PCで再開）

- **実写画像の取り込み**（唯一の未了項目）。詳細パネルに「Mapillary の取得待ち」と出る状態。
  - **Wikipedia の `prop=pageimages` はトークン不要で取得できることを検証済み**。
    4種（Xanthorrhoea / Cecropia / Araucaria angustifolia / Quercus suber）で
    実際に画像を目視し、種と特徴が写っていることまで確認した。
    ただしコルクガシは**肝心の剥皮された赤い幹が見えない**ので差し替えが要る
    → 48種すべて1枚ずつ目視確認する前提で進めること。
  - Mapillary（要トークン）は車載目線なので本番の見え方に近い。
    図鑑寄りのWikipediaと役割が違うので**両方入れる**方針で合意済み。
  - Artifactの16MB制限があるため、点ごとではなく**種ごとに2〜3枚**。
- 余力があれば: クイズモード（点を出して種名を当てる）、種の追加、地域の深掘り。

## 気づき・設計判断メモ

- **カテゴリ色は「識別」ではなく「隣接の区別」と考えると必要数が激減する**。
  地図の四色定理と同じ発想。48→10色で情報量は落ちていない（識別はラベルが担うため）。
- **教材で「空白を埋めたくなる」誘惑に乗らない**。カバー率を上げること自体が目的化すると、
  根拠のない点を置いて教材の信頼性を落とす。
- **Artifactは外部通信できない**ので、地図データも画像も全部埋め込む必要がある。
  これが「点ごとに写真」を諦めて「種ごとに写真」にした直接の理由（16MB制限）。
